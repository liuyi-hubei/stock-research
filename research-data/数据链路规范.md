# 研究数据链路规范

版本：1.0；2026-10-25。适用于本地、Work及其他agent共同维护本项目的数据。本文是数据存储、读取与更新的唯一主规则；写报告仍遵守大师思维的个股研究规范。

## 1. 分离三条链路

数据链路：查库存 → 判断缺口/时效 → 定向取数 → 保存证据 → 标准化 → 校验 → 接受快照。

研究链路：选定数据快照 → 判断商业模式/文化/未来现金 → 记录情景假设 → 更新报告及全部关联出口。

发布链路：本地验收 → 用户确认 → 提交/推送 → 服务器发布。数据入库不等于改报告，更不等于授权发布。不能因数据变了自动调盈利假设、回报门槛或排名资格。

## 2. 目录与权威边界

```text
research-data/
  数据链路规范.md                   # 人和agent都从这里开始
  AGENTS.md                        # 就近协作入口
  registry.json                    # 证券注册表；保留代码前导零
  schema/snapshot.schema.json      # 单个数据快照的机器协议
  sources/*.json                   # 来源元数据、定位及证据文件SHA256
  evidence/*.md                    # 已审阅、无凭据、可共享的取数证据
  securities/XSHG.600519/
    current.json                   # 各数据集已接受版本指针及SHA256
    quotes/*.json                  # 行情快照；文件不可原地改写
    financials/*.json               # 财报快照；按报告期、版本分开
    dividends/*.json                # 分配及除息事件
    operating/*.json                # 月度/季度经营数据
    events/*.json                   # 重大公告事实
  raw-local/                       # 忽略Git的原始下载，非跨设备依赖
```

`research-data`是可复用事实层；`data/*.js`是网站发布投影；`data/research/*.js`是研究判断及正文。严禁从网页四舍五入文案反推数据库。规范化数据和必要的无敏感证据可以随Git共享；整包工作簿、Cookie、个人帖子全文、登录态和密钥不得进入仓库。原始取数目录可以保留，但不再是后续agent唯一可读的证据。

网站不直接加载本目录。部署同步应排除`/research-data/`。即使有此排除，公开GitHub仓库仍是公开的，不能靠不部署来保护秘密。用户未授权推送时只建本地文件。

## 3. 实体、键与粒度

| 实体 | 定义与主键 | 边界 |
| --- | --- | --- |
| 证券 | `securityId=交易所.代码`，如`XHKG.00700`、`XSHE.000568` | 公司A/H股分别建档；名称不是主键；代码为字符串 |
| 快照 | 一只证券、一个dataset、一个asOf、一次取数版本；全局唯一`snapshotId` | 同日重取、公告更正都新增文件，不覆盖旧文件 |
| 观测值 | `snapshotId + observation.id`；同快照内id唯一 | 指标、期间、合并范围、币种、会计标准、调整方式及股数口径共同决定是否可比较 |
| 来源 | 全局唯一`sourceId`，精确指向一份证据及其SHA256 | 同一数据链重复返回不等于独立交叉验证 |
| 当前指针 | 每证券`current.json`按dataset指向一个已接受快照 | 不是按文件名最大值自动选取；冲突数据不能覆盖指针 |

`schemaVersion`管理协议版本；`asOf`是该快照的观测截止日；`collectedAt`是实际获得数据的日期，不能伪装为观测当天已知。`publishedAt`放来源中，未知用null，不能用下载日代替。日期均用ISO格式，日历时效按Asia/Shanghai计算。财报期间放每个观测的period，不能用行情日代替。

当前支持XSHG/XSHE/XHKG三个交易所、CNY/HKD/USD三种计价币种；新增其他市场先扩展注册和校验协议，不随意伪装为现有代码。schema验证器覆盖本仓协议使用的关键字，不宣称是通用JSON Schema引擎。

## 4. 观测结构与指标口径

快照必须包含`schemaVersion / snapshotId / securityId / dataset / asOf / collectedAt / acceptance / createdBy / observations`。数值统一存**十进制字符串**，不带逗号、百分号或亿/万；缺失用null并填`missingReason`，不能写0。`rawValue`保存供应商原显示值；显示舍入不改变标准值。公司预测及外部预测必须明确nature，不能放进历史事实而不标注。

| metric | 含义与单位 | 必须说明的边界 |
| --- | --- | --- |
| close | 指定交易日不复权收盘价；currency_per_share | 上市币种、证券类别、交易日；不是盘中价或复权历史价 |
| pe_ttm | 服务商近十二个月市盈率；times | 服务商盈利口径；负值保留，不与正常化/退出PE混用 |
| pb | 服务商市净率；times | 净资产分母及服务商口径；不能仅按价格比例机械刷新 |
| market_cap | 服务商市值；currency | 供应商归属口径，A股价×全股本不等于A/H实际市值之和 |
| shares_outstanding | 服务商股数；shares | 总/流通/加权/稀释股数分开；近似数不得覆盖模型精确分母 |
| revenue / net_profit_parent / adjusted_net_profit_parent | 营业收入/归母利润/调整后归母；currency | 合并/母公司、会计标准、实际期间；调整后利润列完整调整桥接 |
| operating_cash_flow / ppe_cash_payments / intangible_cash_payments | 经营净现金/现金购建/无形资产付款；currency | 流量期间、现金表位置；购建现金不等于公司资本开支指标 |
| company_capex | 公司披露的资本开支；currency | 公司定义、确认时点；不能与现金购建付款替代或重复扣减 |
| cash / restricted_cash / interest_bearing_debt | 指定日资产负债存量；currency | 归属、受限、债务类别；不能直接当普通股可分配净现金 |
| dividend_per_share | 一笔分红的每股现金；currency_per_share | 所属年度、公告/股东大会批准/实施状态、除息日、付款日、税费和币种；已派和未来预测不得重复计入 |

新增经营指标使用清晰的snake_case名称，同时在观测notes写含义、计量单位和范围；重用同名指标不得改变定义。不同会计标准、不同业务范围、年度累计与单季等不能直接拼接；H1到9M的单季推导须明确输入、差额公式及可比性。比例用小数字符串，如分红率`0.35`；估值倍数则为`13.15`，二者不能混淆。

每条观测含`period`、`basis`、`nature`、`verification`、`sourceRefs`、`notes`。`basis`至少说明scope/accountingStandard/adjustment/shareBasis；不明写unknown/provider_defined，不猜。`sourceRefs`精确到sourceId与表格/页码/单元格定位。`nature=derived`另给`derivation.formula`和不可变输入引用；研究者未来利润、增长率、退出PE和回报门槛继续放模型层，不伪装成数据事实。

分红另填`eventDetails`：announcedAt/approvedAt/exDate/paymentDate（未知为null）、distributionStatus（proposed/approved/implemented/cancelled/unknown）、taxBasis、fiscalPeriod。不得把公告日当除息日。业务/地域等可比维度放`dimensions`字符串键值，不靠同一指标名称混合所有分部。首次新增其他事件类型，先定义其必需字段和校验再接受，不把模糊事件笔记冒充完整结构化事件库。

## 5. 接受状态与证据状态不同

- 快照`acceptance`：staging（候选）、accepted（通过协议和来源检查、允许复用）、rejected（不使用）。accepted不表示全部事实独立审计通过。
- 观测`verification`：provider_reported（接口返回）、source_extracted（读过原件提取）、cross_checked（注明独立核对依据）、conflicted（未解决冲突）、missing（缺失）。不能仅因为另一个agent读过就升级。
- 历史/当前、事实/预测、部分/完整分开。空值、缺口和冲突都保留；财务档案未建立时明确缺失，不把旧报告摘要搬过来称最新财报。

## 6. 默认读取与补数

1. 先读registry和目标证券current；按sourceRefs读取证据，核对所需期间、指标、口径和状态。可以只读取所需数据集，不必每次读取全池。
2. 命令`show`按截止日选已接受快照，默认拒绝含conflicted/missing的快照。历史研究另设`--known-on`，同时限制实际取数日，避免用未来才获得的材料冒充当时已知。
3. 行情默认超过30个日历日提示复核；月度经营数据超过60日提示复核；财务截止超过240日提示复核。它们是缓存复用提示，不是最新认证。新财报、除权除息、股本变动、重大并购及会计更正会提前使旧口径失效；无法确认时标待核。
4. 用户说“最新/当前股价”时，已有快照不自动满足：先确定目标交易日，必要时仅补行情；确认新公告时仅补对应财报/事件。不得将旧价改日期。用户接受历史快照时无需重复取同一份不变财报。
5. 缺失、过期或事件触发才定向补数。妙想优先；第一次失败/不可用缩小范围重试，第二次仍不可用才网络兜底，记录失败和兜底原因。原公告、交易所及公司原件优先于二手解读；行情服务商数据保留供应商口径。
6. 没有采集器自动后台跑，本次CLI只读本地，不连接妙想/网络。不同电脑没有妙想时可以读已共享快照；缺失证据不能靠另一台电脑绝对路径补齐，须重新取得或明确限制。

## 7. 更新协议与多人协作

同一证券同一dataset同轮只允许一个写入者。分配范围后先记录旧current指针SHA256。先新增来源/证据，再写staging候选；完成字段、日期、单位、来源、重复、价格精度及差异核对后才接受。校验程序只检结构和可追溯性，不自动批准事实。

接受时新增一个accepted版本，写current指针和该版本SHA256；旧快照保留。更新前重读指针，与开始时不同则停止晋级并合并差异，禁止最后写入者直接覆盖。Git冲突须人工解决；`git pull --ff-only`也不能代替事实冲突审查。不依赖可遗留的lock文件来宣称已实现跨电脑互斥。

内容更正新增快照，填`supersedes`指向被更正版本，并在notes说明；失效/错误旧快照不能用于后来知识时点的当前选择。历史回溯保留当时已知版本。冲突观测可入staging留证据，但不更新可用指针。不要把跨币种、跨股类、不同期间的差异直接判为来源冲突。

更新记录至少写：runId、执行agent、目标证券/数据集、旧/新snapshotId、变化及来源、未解决项、是否更新网站投影。共享registry及模型/报告投影由集成人串行修改；数据采集者不擅自接受他人未核的估值假设。

记录存`runs/<runId>.json`，不可用“已同步”替代逐证券旧/新版本列表。一次性迁移工具`docs/seed-research-data.mjs`只接受本次已核行情、输出apply_patch且拒绝覆盖已有文件；它不是日常刷新器。日常更新按本节协议新增版本，不能删除已有快照后重跑种子工具。

## 8. 与网站的衔接及验收

读取事实后，由获授权agent明确把所选快照映射到`data/stocks.js`/`data/additional-stocks.js`，记录snapshotId；研究时在正文证据引用同一版本。不自动改模型。报告更新按既有规则同步正文、摘要、归档、榜单和说明。数据层与网站投影有差异时先报告，不静默覆盖。

```bash
node docs/research-data.mjs validate
node docs/check-research-data.mjs
node docs/research-data.mjs inventory
node docs/research-data.mjs show XHKG.00700 --dataset quotes --as-of 2026-10-23
node docs/research-data.mjs show XHKG.00700 --dataset quotes --as-of 2026-10-23 --known-on 2026-10-23
```

最后一条在本次库存中应找不到：这些行情是10月24日取得，不能声称23日已经入库。show显示快照路径、证据状态及缓存年龄；结构验证失败、找不到合格快照、关键缺失/冲突都非零退出。使用`--allow-stale`可显式读取旧快照，但不得称最新；回溯日期仅代表所选快照截止，不证明发布日已知。

网站内容变更后继续运行AGENTS既有全套测试。数据链路不依赖Node外部包、数据库服务或某台电脑的绝对路径，未来数据量很大再考虑SQLite，不提前引入后端。

命令在Git仓库根目录执行，需要本机安装Node.js 18或以上；Windows、macOS使用相同命令。支持仓库文件访问的Work/agent也可直接读取JSON，不必依赖此CLI才能理解数据。
