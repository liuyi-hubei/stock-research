# 证据优先研究的多 agent 并行协作规范

本规范配合 [证据优先个股研究规范](research-framework.md) 使用。执行前读取当前项目 `AGENTS.md`、[研究与更新规则](research-method.md) 和 `README.md`。本文规定多人协作边界，不要求每轮启动子agent；当前写作规则以技能内个股研究规范为准。公共实现由唯一集成人串行处理。是否实际完成以本轮交接与验证记录为准，不创建用户聊天或擅自建立worktree。

## 一、分工原则

只有任务授权允许、确有独立写集合且并行有益时才采用多agent；单股或小任务可由一个agent完成。采用并行时：按股票拆分独立研究任务，让多个研究 worker 同时取证、分析或重组各自股票，再由唯一集成人串行写入共享文件。单股在同一轮只由一个研究 worker 负责写入；跨股共用文件即使修改区段不同，也不能多人同时写。可安排独立审阅者并行只读核验，但审阅者不与作者并发修改同一股票。

| 角色 | 负责内容 | 写入边界 |
| --- | --- | --- |
| 父 agent / 集成人 | 拆分任务、维护认领记录、审核证据与 authority、应用共享补丁、生成和总体验收 | 全部共享文件的唯一写入者；不得借集成扩大用户授权 |
| 单股研究 worker | 一只股票的六章、来源关系、反证、假设与缺口、3—5 个跟踪指标及偏差台账 | 仅认领的独立文件；共享数据修改只能交最小 patch |
| 工程 worker（需要时） | 渲染协议、校验或独立工具实现 | 仅被明确分配且无写入重叠的文件；共享渲染/模型文件仍交集成人应用补丁 |
| 审阅者 | 检查事实定位、推导、状态、参数差异及测试记录 | 默认只读，交付定位到文件/字段的发现与修正建议 |

例如获得并行授权的三股任务可同时安排 000568、002555、002714 三个研究 worker，各自交付一个独立框架文件与研究交接；父 agent 负责共享渲染、加载、生成与核验。不将单一共享文件拆给三人同时直接保存来充当并行。

不擅自新建 worktree，不创建用户侧新任务或聊天。需要子 agent 时使用当前会话可用的子 agent 机制；没有该能力时如实记录未实际并行，不以创建用户任务替代。本文也不授权向其他聊天发送消息。

## 二、开始前认领与基线

父 agent 先读 `git status --short`、当前 diff 和目标文件，识别已有未提交改动与其他正在进行的任务。HEAD 不能代表 dirty tree 的实际输入，因此每项任务须同时记录基准 commit 和已读取文件的 SHA-256。新文件记录“不存在”，不要虚构哈希。

认领记录至少包括：

| 项目 | 必填内容 |
| --- | --- |
| 任务与股票 | 任务标识、股票代码/市场、工作类型（历史重组/新取证/改参/工程）及排除范围 |
| 角色 | 父 agent、研究 worker、工程 worker、只读审阅者；明确唯一集成人 |
| 写集合 | 精确到文件路径；共享文件另列“只读，提交 patch”，不以目录通配符授权 |
| 输入基线 | 仓库绝对路径、基准 commit、每个关键输入的 SHA-256、已有 dirty diff 的归属及需要保留的段落 |
| 参数变更 authority | 用户授权的原文或可定位记录、允许的股票/字段/动作；没有授权时写 `none：仅重组，不改参数/日期/排名资格` |
| 交付与检查 | 预期产物、依赖、来源索引约定、验证命令、交接对象及完成状态 |

推荐只读命令在仓库根目录执行：

```powershell
git status --short
git rev-parse HEAD
git diff --name-only
Get-FileHash data/stocks.js,data/additional-stocks.js,assets/shareholder-model.js -Algorithm SHA256
```

认领不是排他锁。文字写“已锁定”不会阻止其他进程、agent 或用户编辑；不能因认领成功就假设文件保持不变。每次应用补丁前重新读取目标并比较哈希，应用后记录新哈希与差异。若同一文件被别人改动，先定位重叠；保留新内容、按最新上下文重做最小 patch，无法消除歧义时报告具体冲突，不整文件覆盖。

用户授权历史重组不等于授权金融数据刷新、模型改参、排名恢复或发布。worker 发现旧假设问题应形成证据与建议；集成人须在 authority 覆盖范围内处理，不把“修复模板”解释为调参许可。

## 三、文件所有权与共享写入

建议每股新增data/research/CODE.js，使用window.RESEARCH_FRAMEWORK[code]注册正文；新报告为company-study-v2，旧报告兼容evidence-first-v1，按对应版本使用六章ID，不复制原财务参数。独立文件由对应单股worker负责，加载顺序、注册初始化、页面消费和归档接入由集成人统一完成。

| 文件集合 | 写入方式 |
| --- | --- |
| `data/research/000568.js`、`002555.js`、`002714.js` 等独立框架文件 | 一股一 worker；各文件可并行，父 agent 交接后再接管，不与 worker 同时编辑 |
| 对应股票人工报告/核验记录 | 仅在明确认领且不属生成区时由单股 worker 编辑；以任务认领为准，不得进入其他worker的写集合 |
| `data/additional-stocks.js`、`data/stocks.js` 与跨股来源/模型数据 | 唯一集成人串行应用最小 patch，研究 worker 只读并提交建议 |
| `assets/app.js`、`assets/shareholder-model.js`、共用 CSS、共享验证与导出脚本 | 唯一集成人串行落盘；工程 worker 可提供基于基线的补丁 |
| 生成文件、报告自动审阅区、模型说明、加载注册与四入口缓存 | 仅集成人执行或更新，禁止 worker 各自生成或改缓存 |

即使后续某股仅需在 `data/additional-stocks.js` 修改一个字段，它仍是跨股共享文件，必须单写集成。严禁不同 worker 并发整文件重写、各自序列化全池、用旧副本覆盖新内容，或在末尾无条件追加可覆盖更晚审核的历史补丁。研究 worker 交出的最小 patch 应带股票对象/字段定位、旧值与新值、上下文、基线哈希和证据，不包含其他股票的格式化差异。

`stock.sources` 的顺序会影响新框架的 0-based `sourceRefs`。worker 按已认领基线提供映射，集成人调整共享来源后必须逐项重核索引，不能只验证索引未越界而忽略引用错位。

## 四、并行到集成的执行顺序

1. 父 agent 建立范围、基线和写集合，确认多个 worker 之间没有文件写入重叠；用户已有未提交内容属于输入，不要求先清空工作区。
2. 多个单股 worker 并行工作，各自按“事实→推导→假设→缺口”组织六章，记录来源定位、反证、跟踪指标与偏差台账。历史重组不开展未经授权的行情刷新或推测性调参。
3. 审阅者可并行只读检查原始证据与逻辑，不以文字数量、日期数量、模板齐全或脚本通过判断研究可靠。未取得原始资料不能称可靠预测；继承资料注明没有本轮重新取证。
4. worker 完成交接后停止写入该产物，由父 agent 接管；父 agent 核对六项交接、最新哈希和 authority，逐股检查后串行应用共享 patch。
5. 集成人核对实际结构：`version`、`code`、`methodReviewedAt`、`reviewState`、`businessType`、`summary`、六章 `sections`；section 含 `intro`、`blocks`，证据块含 `claim/basis/counterpoint/state/sourceRefs`。不另建与父 agent schema 不兼容的中间协议。
6. 所有研究补丁与工程接入完成后，集成人统一运行必要生成器、更新四入口缓存及只读验证，处理一致性问题。失败时回到具体证据或补丁，不靠降低校验或调参让检查通过。
7. 完成范围与输出核对，向用户交付本地结果、测试记录及剩余缺口。不自动 commit、push 或 deploy。

这套顺序适用于实际采用并行的任务，单agent任务无需虚构并行；共享写入和最终集成始终串行。若工具或依赖使某部分不能并行，应说明实际限制，不能用“多 agent 规范已写好”冒充已经运行多个 agent。

## 五、交接六项与测试记录

每个 worker 的交接必须包含以下六项，不能只交一句“完成”：

1. **范围与基线**：股票、角色、写集合、基准 commit、输入/输出 SHA-256，哪些既有 dirty 改动被保留；共享文件是否变化。
2. **研究结论与状态**：六章内容摘要、`conditional` / `pending` 等状态理由、主要反证、阻断项与未完成项；不将研究状态直接当排名资格。
3. **证据账本**：事实、推导、假设、缺口分列；关键命题提供来源标题、日期、页码/表名、主体/单位，以及 `stock.sources` 索引映射；说明哪些仅继承。
4. **参数与 authority**：逐项说明参数、股本、行情/财报/研究日期、首年股息、模型状态及资格是否变化；有变化则列旧/新、证据和明确授权；无变化也应确认。
5. **产物与最小 patch**：独立文件路径、共享文件补丁、受影响出口和集成顺序；不要包含无关格式化或整文件替换。
6. **验证与后续动作**：实际测试命令、运行时间、所用基线/文件哈希、退出码与关键输出，失败/未运行的原因，待由集成人执行的检查及需补证内容。

测试记录须区分“已运行通过”“已运行失败”“未运行/待集成”。不得复制上一轮 PASS 作为本轮结果，也不能把校验脚本存在当作已执行。金融事实核验、模型一致性、生成同步与浏览器交互是不同证据，不能相互替代。

## 六、集成人的生成、缓存与验收职责

生成器只由集成人运行，包括 `docs/gen-model-explained.mjs`、`docs/sync-model-review.mjs`、`docs/export-stock-archive.mjs`、`docs/render-archive.mjs` 及任务涉及的其他导出器。先检查工具是否覆盖现有人工正文、归档或其他 agent 的成果，只运行授权范围所需的生成动作；不得全量重写来解决局部差异。

四个动态入口 `index.html`、`reports.html`、`stock.html`、`industry.html` 的脚本加载及 `?v=` 缓存戳只由集成人维护。增加框架文件时检查注册初始化与加载顺序、原数据及共同引擎的依赖，并同步相关导出/发布依赖检查。worker 不为自己的文件单独更新入口缓存。本轮这些入口与生成器由集成人维护，worker不得改动。

后续涉及运行时接入时，集成人在仓库根目录按项目要求执行适用检查，并保存输出：

```powershell
node --check assets/app.js
node --check assets/shareholder-model.js
node --check data/stocks.js
node --check data/additional-stocks.js
node --check data/industries.js
node docs/validate.mjs
node docs/check-shareholder-model.mjs
node docs/check-report-numbers.mjs
node docs/render-archive.mjs --check
node docs/gen-model-explained.mjs --check
node docs/sync-model-review.mjs --check
node docs/check-publication.mjs
node docs/check-research-framework.mjs
node docs/sync-research-framework.mjs --check
git diff --check
```

新增独立框架文件另做语法检查、六章结构、来源索引与实际来源一致性检查；按影响补跑价格试算、相关股票回归及真实浏览器桌面/窄屏测试。浏览器结果检查页面、目录、表格、试算、暂停状态及控制台，不以 VM 路由检查代替交互。记录实际视口，涉及布局时覆盖项目要求的 320/390/430/1440 宽度。

三股历史重组还须比较集成前后的模型参数、日期、资格和同引擎输出，确认 000568/002555 仍为条件研究、002714 仍为 `pending` 且 `evaluate` / `sensitivity` 为 `null`，三股无 `ready`，其他股票未迁移。比较以本次文件基线为准，不把历史排名数量或 IRR 快照写成永久测试常量。新框架不因填满章节、通过测试或方法审阅而自动恢复排名。

仅文档任务只做指定 Markdown 的审阅、相对链接和空白检查，以及写入范围核对；不运行可能改写全站的生成步骤，不宣称完成金融事实或浏览器验收。

## 七、dirty tree、冲突与发布边界

保留用户和其他 agent 的所有未提交工作，不执行硬重置、整文件回退、清理未跟踪文件或以 pull 覆盖本地进度；本任务无需拉取远端。哈希变化本身不等于冲突，但必须检查实际差异后再合入，不盲目覆盖或撤销。

发现共享写入碰撞时停止写该文件，汇报路径、重叠字段、基线与当前差异；其他互不依赖的研究工作可继续。父 agent 按证据和最新文件串行重做补丁。确需用户决定的只报告会实质改变结果的分歧，不为日常无冲突集成反复索要确认。

参数变更、模型撤回/恢复和排名决定必须有对应 authority 与证据；禁止借模板升级改变这些结果。每个子任务的写权限以其明确认领记录为准；规范、内容、共享实现与发布不能互相推导权限。

没有明确发布授权，不 commit、push、deploy，不触碰线上。即使后续获准发布，根目录也只能是 `D:/code_files/stock_research/github_file/stock-research`，不得上传上级工作区、`mx-skills`、原始取证或其他非网站内容。验证通过不等于发布授权；推送 `main` 可能触发服务器后续自动发布，不能当作普通备份。
