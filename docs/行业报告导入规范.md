# 行业报告导入规范

## 使用方法

直接把文件或复制的正文发给Codex，并说明报告名称、行业、来源及报告日期（不知道就保留待核），说“加入行业研究，先本地确认”。也可把原件放到总项目 `inputs/industry_reports/`。不需要先转格式。网站没有上传后台，文件落盘不代表已生成网页。

## 原件与网页分开

- `inputs/industry_reports/`：收件与原始HTML等不适合直接公开的文件，不是网站发布目录。
- `reports/industries/`：供溯源下载的PDF或整理后的Markdown；图像可置于 `assets/industry-reports/<报告id>/`。
- `data/industries.js`：统一页面的结构化正文；注册后自动出现于行业列表。
- `industry.html?id=<唯一id>`：报告阅读入口。

导入不是重新研究。不擅自刷新行情、修改原观点或声称原数据已核实。原文数字有冲突、缺页、识别不确定时标注问题，不能猜数补图。

## 三种来源

### Markdown

解析标题层级、段落、列表和表格，提取摘要但不篡改语义；保留脚注与来源。原文自带HTML应作为文本或安全结构处理。图片复制到独立资源目录、修复相对链接并注明来源，不依赖不稳定远程图片。

### HTML或网页复制

只提取研究正文，去掉导航、广告、页脚、脚本、事件属性、iframe、表单和原站CSS。不能把未经处理的原HTML放进公开静态站点，也不能直接innerHTML执行粘贴文本；正文转为文本数据块、表格及经过核验的资源。链接只允许可信https或已核本地资源，禁止javascript/data执行链接。原件留在非公开收件目录，可公开整理后Markdown，不为便利扩大服务器发布白名单。

### PDF

数字版提取正文和表格；扫描版先OCR再逐页核对。多栏阅读顺序、脚注、负号、小数点、单位和表头必须人工核验。图表有可靠数值才重建网页图；没有数值时使用清晰的原图并提供原文，不从柱长猜数字。保留PDF下载，不能把整篇报告拼成不可搜索的图片墙。

## 通用数据字段

报告最少包含 `id/title/date/coreConclusion/sections`。日期未知明确写“待核”，不以导入日期代替报告日。

- `summaryTitle`：可选摘要标题，缺省“核心观点”，禁止模板写死某行业判断。
- `kicker/subject/author`：专题、覆盖对象及作者或机构，缺失不编造。
- `stats/aside`：可选指标数组，元素 `label/value/note`，按实际报告设置，不能强制每篇有PE/PB。
- `nav`：可选章节导航；缺失由sections生成。模板补摘要/来源，去除重复。
- `sourceFile: {href, format}`：原文地址及格式，例如PDF、Markdown；兼容旧 `pdf` 字段。本地地址限已检查 `reports/` 文件，外链限https。
- `sourcesNote/disclaimer`：来源与适用边界。
- `sections: [{id,title,sub,blocks}]`：唯一锚点；正文块支持p、h3、bullets、numbered、table、panels、evidence、chart。
- `table: {head,rows,caption?,note?}`：表头与每行列数一致，三列以内紧凑排版，多列保持容器滚动。

图表、附件链接、章节id、来源、单位必须检查；不把可缩放网页图表当作数据真伪的证明。

## 验收与发布

1. 对照原件检查章节、正文、表格、图表、注释，无遗漏/重复。
2. 原件、结构化数据、列表与下载入口关联完整。宽表只在容器滑动；320/390/430/1440宽度无整页溢出。
3. 执行 `node --check data/industries.js`、`node docs/check-industry-template.mjs`、`node docs/validate.mjs`、`node docs/check-publication.mjs`、`git diff --check`，并查看真实浏览器。
4. 先本地交付确认，再按用户授权发布；不得自动推送，main推送影响服务器定时发布。
