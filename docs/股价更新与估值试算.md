# 股价更新与估值试算

## 一、网页单股试算

个股页“十年股东现金流收益”内输入试算买入价，立即重算悲观、基准、乐观 IRR、基准回报差额与试算价相对参考价的距离。使用原 ShareholderModel 引擎，不增加另一套估值口径。

输入只保留在当前页面内存中，不保存、不写报告、不改变首页排名；刷新页面或点击“恢复研究基准价”还原。人民币和港元按原报告币种输入，不能混用 A/H 股价格。非法输入隐藏旧试算结果并提示错误，不静默回退。

盈利、股数、分红时序、退出估值和回报要求全部沿用原报告。相同现金流下参考价不随买入价变化。试算沿用原行情日的股息领取权，而不是模拟今天买入；跨除息、送转、拆合股、增发等边界时，须先正式复核。报告暂停排名者仍为条件演算，不因低价恢复资格。

功能为纯浏览器运算，确认后发布同一静态代码即可在服务器网站使用，不需要服务器行情接口。

## 二、低频全站正式更新

由用户按需发起，例如“更新全站最新股价，先本地确认”。不新增自动取行情任务或网页全站更新按钮，不部署行情服务。现有服务器代码部署定时器与行情取数无关，不在本任务中修改。

1. 先读 AGENTS.md 和项目 mx-skill，检查未提交改动。按市场与代码列出完整研究池，包括暂停排名的公司，不只处理前十。
2. 优先妙想查询最近已完成交易日的未复权收盘价，节假日保留真实交易日，不填查询日冒充行情日。明确公司、A/H 市场、代码、币种、来源和查询时间；不把盘中价混入收盘快照。
3. 首次失败或缺字段先聚焦同一事实范围重试一次；仍不可用才用交易所、公司投资者关系或可靠行情来源补充，记录兜底理由与链接。冲突、停牌或缺行情逐股明示，保留旧价格和日期，不猜价，不宣称全池已更新。
4. 保存本批中文核验记录，含逐股旧价/旧日、新价/新日、来源、失败项和处理边界；不要在公开文件或网页存入密钥、Cookie、令牌。
5. 核对新行情日是否跨除息或每股口径变化。尤其检查 firstDividendParts、固定首年股息、送转及股数；不机械只改 price/priceDate。若新日期改变未来分红领取权，现金流及参考价可能改变，应单独说明。只有现金流和回报要求均不变时，参考价不变。
6. 通过核验后逐股更新结构化 price、priceDate 和行情来源。盈利路径、回报要求、证据资格与 researchDate 不因刷新股价自动改动；只改价格明确标“沿用原报告盈利假设”，不得宣称已重新研究最新财报。
7. 使用同一引擎重算全池三情景、回报差额、首页排序及数量；同步手写估值文案、关键事实、价格对应预测PE、Markdown报告和核验、自动审阅区、模型说明等所有出口。行情口径变化须重新核对市值/PE/PB，无法可靠重算则标待核，不沿用旧值冒称新值。
8. 执行 AGENTS.md 全部一致性检查，以及 node docs/check-price-trial.mjs。逐股验证价格、币种、分红边界、排名资格与输出；出具成功/保留旧数据清单，在本地预览交付。
9. 只有用户确认发布后才提交/推送或操作服务器。推送 main 会触发既有服务器拉取流程，不能把推送当作仅保存本地进度。

本流程不承诺数据供应商持续可用，不把工程校验当作财务事实或投资预测的验证。
